# ADR-0003 · 生成物快照入库策略：保留回溯价值，接受大 diff

- 状态：已接受（2026-10-11，NEXT 落地）
- 背景：`scan-data.json`（扫描快照）、`dashboard.html`（重渲染面板）、`all_repos_report.txt` / `scan_run*.txt`（报告归档）为生成物；每次扫描会产生大 diff（本次在制品 scan-data.json ±3112 行），与代码变更耦合。
- 决策：生成物快照按既有惯例随主分支入库（历史多次「chore: 刷新扫描快照与面板」提交）；快照刷新与代码变更**分批提交**（快照 commit 与重构/文档 commit 分离），便于按提交回溯任一快照；readme 明示该策略。
- 备选方案：
  - A. 快照移出主分支（gitignore + 按需生成）——否决：破坏"clone 即得全量快照"的现状与历史回溯能力，且需移除已跟踪文件（破坏面更大）。
  - B. 快照入 releases 资产——否决：超出当前发布节奏（仅 v* tag 触发），单人使用收益低。
- 理由：历史行为一致（可逆、可回溯）；改动面最小；大 diff 以"分批提交 + 提交信息标注"缓解。
- 影响：快照与代码同库导致每次扫描 diff 较大；已登记于 docs/tech-debt.md 作为持续关注项（若未来多人协作可重评）。
