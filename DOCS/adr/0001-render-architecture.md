# ADR-0001 · 面板渲染架构：单页整体生成 + 客户端应用独立资产

- 状态：已接受（2026-10-11，NEXT 落地）
- 背景：`dashboard.html` 由服务端 `renderDashboard` 用模板字面量整体生成，客户端应用（筛选/排序/主题/趋势等约 1175 行浏览器 JS）曾内嵌在 `scan-core.mjs` 的模板字面量中，导致核心文件膨胀（2542 行/147KB）且客户端代码无法独立维护。
- 决策：
  1. 客户端应用以独立资产文件 `assets/dashboard-client.js` 存放（纯浏览器 JS，不参与 Node 模块体系），渲染时由 `render-dashboard.mjs` 读取并注入 `<script>` 块。
  2. 渲染职责从 `scan-core.mjs` 拆至 `render-dashboard.mjs`；`scan-core.mjs` 保留取数/合并/统计，re-export 既有导出以保持所有调用方不变。
- 备选方案：
  - A. 引入前端构建链（打包/压缩/版本化）——否决：项目零依赖目标，单人维护成本高，与现有"扫描即生成静态页"闭环不符。
  - B. 客户端逻辑原地不动，仅拆服务端函数——否决：未解决 1175 行客户端内嵌的维护与回归问题。
- 理由：可逆性最高（行为零变化、可回滚）；与现有架构一致性最高（仍由服务端整体生成单页 HTML）；改动面最小（re-export 保持 import 站点不变）。
- 影响：客户端脚本不再受外层模板字面量转义影响（`\n`/`\s` 被"吃掉"的风险面收窄），但注入内容仍须避免裸 CR 与 `</script>`（测试守卫保留）；渲染模块读取资产文件，缺失时渲染抛错（测试覆盖）。
